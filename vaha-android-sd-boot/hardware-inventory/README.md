# hardware-inventory/

Machine-readable inventory of the VAHA X / ShiMeta IoT-3399E as the stock
Android 7.1.2 installation configures it.

**Empty at present.** No data has been collected; this session had no access to
the device. See `../HARDWARE-INVENTORY.md` for what belongs here and why.

## How it gets filled

With the VAHA powered on and ADB connected, from the project root:

    scripts/collect-inventory.sh

Everything that script runs is read-only. Nothing is written to the device.

Without the VAHA, from the partition backups alone:

    scripts/extract-dtb.sh /path/to/backups

That recovers the stock device tree, which is the single most valuable artefact
in the project, and needs no device access at all.

## File conventions

Every collected file is plain text unless the extension says otherwise, and
starts with a three-line header so the file is self-describing:

    # <what this is>
    # command: <exact command that produced it>
    # collected: <ISO 8601 timestamp>

Binary artefacts are `device-tree.tar.gz` (tar of `/proc/device-tree`),
`stock.dtb` (the extracted device tree blob) and `rk-kernel.dtb` (as named inside
the Rockchip resource container).

`MANIFEST.sha256` lists the SHA-256 of every other file in this directory and is
regenerated by `scripts/make-manifest.sh`.

## Do not commit

Partition backup images do not belong here. They are large, they are the
recovery insurance, and they should live on storage outside this repository with
their own verified manifest. `.gitignore` excludes `*.img` and `*.bin` for that
reason.
